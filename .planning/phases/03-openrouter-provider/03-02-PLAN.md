**Section 2 — Auth + model table (`## Auth`):**

  - **Common mistake to avoid:** the `openai` SDK default `OpenAI()` (no args) reads `OPENAI_API_KEY`, NOT `OPENROUTER_API_KEY`. Our tool never relies on that default — you shouldn't either when writing new code against this SDK for OpenRouter.
- Get a key at https://openrouter.ai/settings/keys
- Model compatibility table:

  | Model slug | Role | Structured output (`response_format=json_schema`) |

  | `google/gemini-3.1-pro-preview` | Default | Works — structured path is the happy path |

  | Other providers | Variable | Check https://openrouter.ai/models?supported_parameters=structured_outputs |

**Section 3 — Inline-base64 quirks sidebar (`## OpenRouter quirks — what to know`):**

- **Video input is INLINE BASE64 ONLY on the Gemini route.** OpenRouter → Google AI Studio rejects `video_url` values that are HTTP URLs (only YouTube URLs are accepted, which is not a path OpenMontage uses). Vertex AI route rejects URLs too. The tool therefore always encodes `data:<mime>;base64,<payload>`.
- Default `max_upload_bytes = 20 MB` (configurable per call via the tool's `max_upload_bytes` input). Clamped to `[1, 2 GB]` hard cap.
- Supported video MIMEs: `mp4`, `mov` (quicktime), `webm`, `mpeg`. Other types are rejected before encoding.
- Large files (100 MB+) cause base64 memory inflation (~1.33×) and request-body bloat. Keep videos under the default cap or chunk them (Phase 4).
- OpenRouter rewrites `resp.model` to the UNDERLYING provider's model ID (e.g., you request `google/gemini-3.1-pro-preview` and `resp.model` comes back as `gemini-3.1-pro-preview-20XX-MM-DD` from AI Studio). Our tool stores `resp.model` verbatim on `ToolResult.model`; do not normalize it to the requested slug in callers.
- `client.close()` is NOT needed (openai SDK manages context internally).
- There is NO Files API equivalent — no cleanup step. `data_url` lives only in the request body.

**Section 4 — Structured-output pattern (`## Structured JSON output — the happy path`):**

Code block showing the EXACT shape the tool uses:

```python
from openai import OpenAI
from lib.schema_adapter import to_api_schema
from schemas.artifacts import load_schema

FLAT_SCHEMA = to_api_schema(load_schema("video_analysis"))

client = OpenAI(
    api_key=os.environ["OPENROUTER_API_KEY"],   # explicit — SDK default reads OPENAI_API_KEY
    base_url="https://openrouter.ai/api/v1",
    default_headers={
        "HTTP-Referer": "https://github.com/openmontage",
        "X-Title": "OpenMontage",
    },
)

resp = client.chat.completions.create(
    model="google/gemini-3.1-pro-preview",
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "text", "text": prompt},
                {"type": "video_url", "video_url": {"url": data_url}},   # data:video/mp4;base64,...
            ],
        }
    ],
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "video_analysis",
            "schema": FLAT_SCHEMA,
            "strict": True,
        },
    },
    # OpenRouter-specific: force providers that HONOR response_format (Pitfall 4 mitigation)
    extra_body={"provider": {"require_parameters": True}},
)

# Truncation check is STRING equality — NOT an enum
if resp.choices[0].finish_reason == "length":
    # Retry with analysis_depth="compact" — shorter prompts, tighter descriptions
    ...

content = resp.choices[0].message.content or ""
artifact = json.loads(content)
```

State plainly:
- `response_format={"type":"json_object"}` is allowed but WEAKER than `json_schema` with `strict=True` — always prefer json_schema when the route supports it.
- Do NOT use `client.beta.chat.completions.parse()` — that path is OpenAI-specific and does not play nicely with OpenRouter's multi-provider routing. Stick to `.create()` + `json.loads()`.
- `extra_body` is OpenRouter-specific and passed through by the openai SDK verbatim. Do NOT put `response_format` inside `extra_body` — it is a first-class `create()` kwarg.

**Section 5 — Fallback path: prompt-embedded schema (`## Fallback — when the model rejects response_format`):**

Code block showing the fallback:

```python
from openai import BadRequestError

try:
    resp = client.chat.completions.create(
        ...,
        response_format={"type": "json_schema", "json_schema": {...}},
        extra_body={"provider": {"require_parameters": True}},
    )
except BadRequestError:
    # Route doesn't support structured outputs — fall back to schema-in-prompt
    prompt_with_schema = prompt + "\n\nYour response MUST match this schema:\n```json\n" + json.dumps(FLAT_SCHEMA, indent=2) + "\n```"
    resp = client.chat.completions.create(
        model=...,
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": prompt_with_schema},
                {"type": "video_url", "video_url": {"url": data_url}},
            ],
        }],
        # NOTE: no response_format, no extra_body on the fallback — don't over-constrain
    )
    artifact = json.loads(resp.choices[0].message.content)
    # Post-hoc validation is CRITICAL on this path — the model may not honor the embedded schema
    jsonschema.validate(artifact, FLAT_SCHEMA)
```

- **Common mistake:** catching every 4xx as "unsupported structured output." Only `BadRequestError` (400) from an "invalid params" shape should fall back. `AuthenticationError`, `PermissionDeniedError`, `RateLimitError` must propagate — a silent fallback here masks real configuration errors.
- `jsonschema.validate` is essential on the fallback path. The canonical `validate_artifact("video_analysis", artifact)` (from Phase 1's `schemas/artifacts/__init__.py`) is stricter than the flat schema — prefer it when the artifact is what you care about.

**Section 6 — Per-dimension prompting (`## Per-dimension prompting`):**

Four sub-sections (editing_pacing, audio, visual_style, narrative). For each:
- Top-level JSON keys the schema expects (read from `schemas/artifacts/video_analysis.schema.json`)
- Good vs bad extraction example (BAD: `"pacing": "fast"` as a free-form string; GOOD: `"cuts_per_minute": 32, "pacing_style": "frantic"` with confidence map)
- Dimension-specific gotcha:
  1. **`editing_pacing`** — include `shot_boundaries` when available; if absent, tell the model to infer and set `shot_boundary_source: "model"`. OpenRouter routes may truncate reasoning about many shots; prefer pre-computed boundaries for videos with 20+ cuts.
  2. **`audio`** — voice characteristics, music energy, SFX density. Model holistic-audio inference works for videos ≤20 MB; Phase 4 chunking will change the weighting strategy.
  3. **`visual_style`** — `dominant_colors_hex`, `dominant_visual_style`, `typography_style`, motion treatment. Do NOT ask the model to identify typefaces; description only.
  4. **`narrative`** — hook from first few seconds, CTA from the last shot. Section_structure timecodes can drift on videos >5 min even when structured output is on — Phase 4 chunking is the mitigation.

**Section 7 — `finish_reason == "length"` STRING check + confidence-map pattern (`## Truncation, cost, and the "don't trust the enum" trap`):**

Explicit call-out box:

> **Gotcha (differs from Gemini):** The openai SDK's `Choice.finish_reason` is typed `Literal['stop', 'length', 'tool_calls', 'content_filter', 'function_call']`. At runtime it is a **plain string**, not an enum. Code like `if finish_reason == FinishReason.MAX_TOKENS:` copy-pasted from Gemini will always be False against OpenRouter responses — retries will never fire and truncated JSON will crash downstream parsing. Use `if finish_reason == "length":` — string equality.

Confidence-map block (same as Gemini SKILL — this is schema-universal):

```json
"editing_pacing": {
  "cuts_per_minute": 32,
  "pacing_style": "frantic",
  "confidence": {
    "cuts_per_minute": "high",
    "pacing_style": "medium",
    "shot_length_variance": "low"
  }
}
```

Instruction the agent must paste into every prompt: _"For every uncertain or absent field, populate the dimension's `confidence` map with the field-name → `low` entry. NEVER omit a required field and NEVER emit `null`."_

```python
usage = getattr(resp, "usage", None)

# Do NOT do this:
#   resp.response.headers["x-openrouter-credit-remaining"]   # ← this header doesn't exist
```

Explicit warning:

> **Warning:** `x-openrouter-credit-remaining` is NOT a real OpenRouter response header. It appears in some community code examples but is not documented by OpenRouter. The only rate-related headers OpenRouter exposes are the standard `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (and only some routes set them). For per-call cost, use `response.usage.cost` (OpenRouter adds this as an extra field on the standard `CompletionUsage` shape — pydantic preserves it via `model_extra`).
