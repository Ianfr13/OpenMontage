<objective>
Close CLEAN-09 — stop abusing `pipeline_synthesis` as a catch-all for post-accept / post-reject events. Split into two dedicated schemas (`pipeline_acceptance`, `pipeline_rejection`) that only carry fields the event actually has. Delete the sentinel writes (`base_pipeline=slug`, `match_score=0.0`, `source_analysis_checksum="post-accept"`, `"post-reject"`, `validation_status="invalid"` as rejection-proxy) that pass schema validation but violate semantic intent.

Purpose: v2.0 Phase 5 REVIEW MR-02 — current accept/reject records contradict the schema's documented meaning (`base_pipeline` should be the matched base, not the promoted slug; `source_analysis_checksum` should be a sha256 hex, not a literal "post-accept"; `match_score` should be 0-1 from the matcher, not the sentinel 0.0). Downstream audit/analytics consumers that trust the field semantics will silently break. Per CONTEXT.md D-CLEAN-09: schema-split (option 2 from the review) over sentinel allow-list (option 1) — gives honest contracts for honest events.

Output: two new schemas, refactored accept/reject, updated tests, `pipeline_synthesis` schema untouched (still used by `synthesize_pipeline`).
</objective>
