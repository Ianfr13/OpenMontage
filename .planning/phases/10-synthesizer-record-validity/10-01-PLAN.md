    ```python
    def _validate_slug(slug: str) -> None:
        """Raise InvalidPipelineSlug if ``slug`` is unsafe to join under STAGING_DIR.

        Two gates:
          1. Regex ``^[a-z0-9][a-z0-9\\-_]{7,127}$`` — matches the output of
             :func:`_build_slug` (``<base>-<hex[:8]>``) and rejects every
             path-traversal / absolute-path payload by construction.
          2. Resolved-path check — defense-in-depth: confirm
             ``(STAGING_DIR / f\"{slug}.yaml\").resolve()`` stays under
             ``STAGING_DIR.resolve()``.

        Raises:
            InvalidPipelineSlug: on any failure (never ValueError).
        """
        if not isinstance(slug, str) or not _SLUG_RE.fullmatch(slug):
            raise InvalidPipelineSlug(
                f"Invalid slug {slug!r} — must match {_SLUG_RE.pattern!r}"
            )
        # Defense-in-depth: resolved path must stay under STAGING_DIR.
        candidate = (STAGING_DIR / f"{slug}.yaml").resolve()
        staging_resolved = STAGING_DIR.resolve()
        if staging_resolved != candidate.parent:
            raise InvalidPipelineSlug(
                f"Slug {slug!r} resolves outside staging root {staging_resolved!s}"
            )
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| meta-skill CLI → accept_synthesis(slug) / reject_synthesis(slug) | `slug` originates outside the module; today it's constructed by _build_slug (hex only), but the API surface is public and an upstream refactor could surface user input here without the synthesizer knowing. This is the boundary CLEAN-08 hardens. |
| _validate_slug(slug) → STAGING_DIR filesystem | Once validated, the resolved path is trusted to stay under STAGING_DIR; shutil.move / unlink operate on it directly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | `accept_synthesis(slug)` — path-traversal via `slug="../cinematic"` could resolve to `pipeline_defs/cinematic.yaml` and `shutil.move` would rename a real pipeline out of pipeline_defs/ | mitigate | Regex `^[a-z0-9][a-z0-9\-_]{7,127}$` rejects `..`, `/`, `\`, `.` (by character class); defense-in-depth `(STAGING_DIR / f"{slug}.yaml").resolve().parent == STAGING_DIR.resolve()` check short-circuits any regex bypass before any shutil call. |
| T-10-02 | Tampering | `reject_synthesis(slug)` — same path-traversal payload could cause `src.unlink()` to delete an arbitrary file reachable from STAGING_DIR via `..` segments | mitigate | Same `_validate_slug(slug)` guard applied at function entry before `src.unlink()`. |
| T-10-03 | Denial of Service | Excessively long slug (e.g., 10KB string) passed to `accept_synthesis` — regex evaluation is linear and `Path` operations handle long strings, but `shutil.move` could fail on filesystems with NAME_MAX limits and leave partial state | mitigate | Regex caps length at 128 characters (`{7,127}$`), short-circuiting before any fs call. |
| T-10-04 | Repudiation | An InvalidPipelineSlug exception is raised but the caller swallows it silently without logging | accept | Caller responsibility; the sentinel class carries the offending slug in its message for audit via `except InvalidPipelineSlug as exc: logger.error(...)` once the meta-skill CLI wraps this in Phase 6+. Out of scope for this phase — documented in deferred ideas. |
