<objective>
Fix v2.0 Phase 4 MR-02 / CLEAN-06: `lib/analysis_merger.py` silently injects hardcoded defaults on 8 required-schema fields when `_weighted_majority` or first-non-null returns None (e.g. `pacing or dims[0].get("pacing_style", "steady_educational")`). This violates the single-validation-gate guarantee — instead of surfacing "no chunk provided this required field" as a clear error, the merger fabricates a value that is schema-valid-but-wrong about the actual video.

Per CONTEXT.md locked decisions, introduce a new sentinel exception `MergeConsensusError` (subclass of `VideoAnalysisError`, mirroring the Phase 8 auth/rate sentinel pattern in `lib/analysis_errors.py`). Replace every `vote or dims[0].get(field, DEFAULT)` pattern at the 8 enumerated line numbers with a guard that raises `MergeConsensusError` when both the consensus AND the first-chunk fallback yield None (which means no chunk ever provided the field — a legitimate upstream bug, not something the merger should paper over).

**IMPORTANT scope clarification** (schema re-validated during planning, 2026-04-18):
- `schemas/artifacts/video_analysis.schema.json` lines 272-283 confirm `target_platform` enum DOES include `"unknown"` — contrary to what 04-REVIEW.md MR-02 claims. So the fallback `"unknown"` on line 637 is schema-valid. But CONTEXT.md and ROADMAP Phase 9 success criterion #2 still mandate removing it because it violates single-validation-gate: the merger is inventing a value no chunk provided. Keep the removal.
- The 8 lines listed in REQUIREMENTS are the strict scope. Line 244 (`first["type"] = "local_file"` in `_merge_source`) also papers-over missing data but is NOT in CLEAN-06 scope — leave it alone (deferred to Phase 11 NITS-01 if desired).

Purpose: merger stops lying about the input. Real upstream bugs (provider tool returning an artifact missing `pacing_style`) surface as a pointed error instead of a downstream `ValidationError` or — worse — a schema-valid artifact containing fabricated values.

Output: `MergeConsensusError` class in `lib/analysis_errors.py`; 8 fallback sites in `lib/analysis_merger.py` converted to guarded raises; targeted unit tests proving each raise; updated tests where they exercised the old behavior.
